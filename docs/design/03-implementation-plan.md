## 1. 作る順番とその理由

```
Step 1 共通部品（設計書の型・品質基準・表現ルール）
   ↓
Step 2 B版（Claude Code Skill）   ← 費用0円で、出力の質を先に確かめる
   ↓
Step 3 出力の質の確認（テスト用ブランド3件）
   ↓
Step 4 A版（Webアプリ）           ← Step 3で質が確認できた型をそのまま使う
   ↓
Step 5 A版の公開
```

**B版を先に作る理由**
- 広告設計書の質を決めるのは「型・品質基準・表現ルール」。B版なら費用もサーバーもかけずに試せる
- B版で直した型をA版がそのまま使うので、A版でAI利用料をかけながら試行錯誤する必要が減る

```

│   ├─ expression-rules.md            … 表現チェックの基準（業種別の注意を含む）
│   ├─ input-fields.json              … 入力17項目の定義（名前・必須・上限文字数・記入例）
│   └─ samples/                       … テスト用ブランド3件（架空）

│       ├─ coaching.json
│       └─ handmade-shop.json
├─ .claude/skills/ad-plan/
│   └─ SKILL.md                       … 【B版】手順・質問ルール。shared/ を読むよう指示する
├─ output/ad-plans/                   … 【B版】作った設計書の保存先（GitHubに上げない）
├─ web/                               … 【A版】Next.jsアプリ
│   ├─ app/page.tsx                   … 画面0・画面1
│   ├─ app/api/generate/route.ts      … Claude APIを呼ぶサーバー処理
│   ├─ app/api/passcode/route.ts      … 合言葉の照合
│   ├─ lib/prompt.ts                  … shared/ の内容からAIへの指示文を組み立てる
│   ├─ lib/validate.ts                … 入力チェック（画面・サーバー共通）
```

**要点**：A版の `lib/prompt.ts` とB版の `SKILL.md` は、どちらも `shared/ad-plan/` を読む。型を直すときは `shared/` だけ直せばよい。

## 5. 想定されるリスクと対策

| リスク | 対策 |
|---|---|
| AIの出力が型どおりにならない | 型を `shared/` に1か所でまとめ、Step 3でB版を使って先に調整する。A版では10章の見出しがそろっているかをサーバー側で確認し、欠けていれば「うまく作成できませんでした」と表示する |
| 合言葉が受講生以外に広まる | 1日10回の制限と月の利用上限で、被害を上限内に収める。合言葉はVercelの設定画面で変えられる |
| 法律上の表現チェックを「保証」と受け取られる | 設計書の最後と画面に「注意喚起であり、最終判断はご自身で」と必ず表示する |
| A版とB版で設計書の中身がずれる | 両方とも `shared/` を読む構成にする |
