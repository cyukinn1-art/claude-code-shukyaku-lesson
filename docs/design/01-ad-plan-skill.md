# ツール設計書：ブランド広告設計ナビ（Claude Code版）

> **ひとことで**：女性起業家が、Claude Codeで質問に答えるだけで、自分のブランドに合ったInstagram／Facebook広告の設計書を作れる仕組みです。
>
> 状態：**設計中（第2稿）**。実装はまだ始めていません。
>
> ※ここで作るのは「広告の設計書を作るSkill（`ad-plan`）」です。ツールの設計書を作るための「設計書作成Skill（`design-doc`）」とは別物です。

---

## 1. ツール概要

| 項目 | 内容 |
|---|---|
| ツール名（仮） | ブランド広告設計ナビ |
| 何をするか | ブランドの情報から、Meta広告（Instagram／Facebook広告）の設計書を作る |
| 誰が使うか | 女性起業家本人 |
| 使う場所 | Claude Code（このリポジトリの中） |
| 費用 | 追加費用なし（Claude Codeの契約内で使える） |
| 最小構成 | 質問に答える → 広告設計書が1つできる。広告文は3パターン付く |

**Skillとは**：Claudeに作業の手順を覚えさせる「説明書」のようなものです。ファイルを置いておくと、Claudeがその手順どおりに動きます。

## 2. 背景と解決する問題

**ひとことで**：思いつきで広告を出して、お金だけ減る状態をなくします。

**今の困りごと（想定）**
- 広告の文章や画像を、その場の思いつきで作っている
- 誰に向けた広告なのか、はっきりしない
- ブランドの雰囲気と、広告の雰囲気がずれる
- 広告を出した後、どの数字を見ればよいか分からない
- ルール違反になりやすい表現を、知らずに使ってしまう
  - 例：「必ず痩せる」（効果の言い切り）
  - 例：「40代でシワに悩むあなたへ」（相手の特徴の決めつけ。Meta広告のルールで禁止）

**このツールを使った後**
- 「誰に・何を・どう見せて・どう確かめるか」が1つの設計書にまとまる
- 危ない表現は、設計書の中で指摘され、言い換え案が出る
- 広告文を3パターン比べて、反応のよいものを選べる

## 3. 使う人

| 項目 | 内容 |
|---|---|
| 使う人 | 個人で事業をしている女性起業家（サロン、講座、コーチング、ハンドメイド、物販など） |
| 知識 | 広告の知識は少ない。Claude Codeは使える |
| 使う場面 | 初めて広告を出す前／広告の反応が悪くて見直したいとき |
| 管理者 | いない |

## 4. 今回作るもの

**ひとことで**：質問に答える → 設計書ができる → 保存される、までを作ります。

**必ず作るもの**
- ブランド情報を聞き取る（質問は少なめ。下の「6. 使う流れ」参照）
- 広告設計書を作る（下の「9. 出てくる設計書の中身」参照）
- 広告文を3パターン作る（共感型／変化を見せる型／ストーリー型）
- 危ない表現をチェックし、言い換え案を出す
- 設計書をファイルに保存する
- 「ここを直して」と言われたら、その部分だけ直す

**あれば便利なもの（今回は作らない）**
- 画像のたたき台を作る
- Google広告やLINE広告への対応
- 広告を出した後の数字を入れると、改善案を出す機能

## 5. 作らないもの

- Webアプリ版（今回は作らない。将来の候補）
- 広告を自動で出稿すること
- 広告費の支払い
- 画像・動画そのもの（何を写すかの案までは作る）
- 法律チェックの保証（注意をうながすだけ。最終判断は本人）
- ブランド戦略をゼロから作ること（ブランドがまだ固まっていない人には、最低限の質問だけする）

## 6. 使う流れ

**ひとことで**：質問は最大2回。あとはClaudeがおすすめで埋めて、すぐ初稿を見せます。

1. 利用者が、Claude Codeで「広告設計書を作って」と頼む
2. Claudeが、**記入シートを1つ**出す（下の「7. 記入シート」）
   - 分かるところだけ書けばよい
   - 自己紹介文やLPの文章を貼るだけでもよい
3. Claudeが、答えを読んで整理する
4. どうしても必要な情報だけ、**最大2問**、おすすめ案を付けて質問する
   - 足りなくても進められるものは聞かずに、おすすめ案で仮に置く
5. 設計書を作る
6. Claudeが、品質基準（下の「10」）で自分でチェックし、直せるところは直す
7. 設計書をファイルに保存し、ポイントをチャットに表示する
8. 「直したいところはありますか？」と聞く

**直すとき**
- 「広告文をもっと上品に」などと伝えると、その部分だけ直す
- 直す前の設計書は、別のフォルダに残す

**情報がほとんどないとき**
- 「ブランドの雰囲気」を決めるための質問を、2問だけする

## 7. 記入シート（最初に出すもの）

**ひとことで**：6つだけ書いてもらいます。残りは任意です。

**必ず書いてほしいこと（6つ）**

| No | 項目 | 例 |
|---|---|---|
| 1 | 広告で売りたいもの（名前と価格） | 「90分の体験レッスン 3,000円」 |
| 2 | 理想のお客様 | 「40〜50代、仕事も家事も頑張っている女性」 |
| 3 | お客様の悩み・叶えたいこと | 「忙しくて自分のケアができない」 |
| 4 | あなたの強み・選ばれる理由 | 「元エステティシャン歴15年」 |
| 5 | 広告の目的とクリック先 | 「LINE登録してほしい」 |
| 6 | 1か月の広告予算 | 「30,000円」 |

**書けたら書いてほしいこと（任意）**
- 屋号・ブランド名
- ブランドの雰囲気（例：上品、やさしい、元気）と言葉づかい（丁寧／親しみ）
- 起業のきっかけ・想い（ストーリー型の広告文に使う）
- 配信したい地域
- 使いたくない言葉

**書かなかった場合**
- 屋号がない → 「あなたのブランド」と書く
- 雰囲気がない → 答えからClaudeが提案し、「仮に置いたこと」に書く
- 業種 → 答えからClaudeが判断する（聞かない）

**お願いの一言**（シートに必ず入れる）
- お客様の名前や連絡先は書かないでください

## 8. 主な機能

| 機能 | やること | できたかの確認 |
|---|---|---|
| ① 聞き取り | 記入シートを出す。足りない分だけ最大2問聞く | 3回目の質問が出ない |
| ② 整理 | 答えを「決まったこと／仮に置いたこと」に分ける | 設計書の最後に両方書かれている |
| ③ 設計書づくり | 下の「9」の10章どおりに作る | 10章すべてそろっている |
| ④ 自分でチェック | 下の「10」の基準で確認し、直す | チェック結果が設計書の最後に付いている |
| ⑤ 保存 | `output/ad-plans/{日付}_{ブランド名}.md` に保存。同じ名前があれば `_2` を付ける | 上書きされない |
| ⑥ 直す | 言われた部分だけ直す。直す前の版は `output/ad-plans/_old/` に残す | 他の章が変わっていない |

## 9. 出てくる設計書の中身

```
# 広告設計書：{ブランド名}（{作成日}）

1. ブランドのまとめ
   - 誰に、どんな変化を届けるかを1文で
   - ブランドの雰囲気 / 言葉づかい / 避けたい雰囲気

2. 広告の目的と目標の数字
   - 目的（例：LINE登録）
   - 見る数字と目安
     - クリック率（広告を見た人のうち、押した人の割合）
     - 1件あたりの費用（LINE登録1人を集めるのにかかった広告費）
   - 予算から見た、1か月の目安の件数（※あくまで仮の計算）

3. お客様像
   - 1人の人物として描いたお客様
   - 悩み → 本当に叶えたいこと
   - 広告を届ける相手の設定案（年齢、地域、興味のあること）

4. 伝え方の軸（3パターン）
   - A：共感型（悩みに寄り添う）
   - B：変化を見せる型（使った後どうなるか）
   - C：ストーリー型（想いや人柄で信頼してもらう）

5. 広告の中身（パターンごと）
   - 本文（最初の約40字で伝わるように。全体は約125字＋長い版）
   - 見出し（約27字まで）
   - ボタンの言葉（例：詳しくはこちら）
   - 画像・動画の案（何を写すか、入れる文字、色）

6. 広告の出し方
   - Meta広告の管理画面で選ぶ「目的」
   - 予算の使い方（最初の1〜2週間はお試し）
   - 3パターンの比べ方
   - 見直すタイミング

7. クリック先との確認
   - 広告で約束したことが、LP・LINEの最初に書かれているか

8. 表現の注意点
   - 危ない表現と言い換え案
   - 業種ごとの注意

9. うまくいかないときの直し方
   - 数字が悪いとき、どこを直すか（画像／見出し／相手の設定／クリック先）

10. 仮に置いたこと・チェック結果
   - 情報が足りず、Claudeが仮に置いた内容
   - 品質基準のチェック結果
   - 「表現のチェックは注意をうながすものです。最終判断はご自身でお願いします」
```

## 10. 品質基準（「いい感じの広告」を具体的にしたもの）

- [ ] ブランドの雰囲気と言葉づかいが、3パターンすべての広告文に出ている
- [ ] 3パターンの中身がはっきり違う（同じ文の言い換えではない）
- [ ] 見出しは約27字まで。本文は最初の約40字で内容が伝わる
- [ ] 「必ず」「絶対」「誰でも」「100%」など、効果を言い切る言葉がない
- [ ] 年齢・体型・病気・お金の悩みなどを、相手に決めつけていない
- [ ] 価格や商品名など、書かれた事実を変えていない
- [ ] 書かれていない実績（「受講生1,000人」など）を勝手に作っていない
- [ ] 目標の数字は「目安」と書かれ、約束になっていない
- [ ] 仮に置いたことが、10章に書かれている

## 11. 危ない表現のチェック表

| 種類 | 例 | どうするか |
|---|---|---|
| 効果の言い切り | 「必ず痩せる」「シミが消える」 | 言い換える（例：「ケアの習慣づくりを応援」） |
| 誰でも・簡単 | 「誰でも月収100万円」 | 言い換える。お金の話は特に注意と書く |
| 一番・No.1 | 「日本一」「業界No.1」 | 根拠が書かれていなければ使わない |
| 相手の特徴の決めつけ | 「40代でシワに悩むあなた」 | 「40代からのスキンケア」など、決めつけない形にする |
| 使う前・使った後の比較 | 写真で比べる | 美容・健康では使わない方向で提案 |
| 医療っぽい言葉 | 「治る」「改善する」 | 使わない |

> 法律（薬機法・景品表示法など）とMeta広告のルールのチェックは、**注意をうながすもの**です。保証ではありません。

## 12. データの扱い

| データ | 保存する場所 | GitHubに上げるか | 消し方 |
|---|---|:---:|---|
| 作った設計書 | `output/ad-plans/` | 上げない | ファイルを消す |
| 直す前の設計書 | `output/ad-plans/_old/` | 上げない | ファイルを消す |
| Skill本体 | `.claude/skills/ad-plan/` | 上げる（個人の情報は入っていない） | — |

- `output/` は `.gitignore` に入れ、GitHubに上がらないようにする
- お客様の名前や連絡先は、書かないよう案内する

## 13. 困ったときの動き

| こんなとき | Claudeの動き |
|---|---|
| ほとんど何も書かれていない | 雰囲気を決める質問を2問だけする |
| 危ない表現が書かれている | 広告文には使わず、8章で指摘して言い換える |
| 書かれた内容が食い違う（上品な雰囲気なのに、言葉づかいはくだけている） | どちらを優先するか、1問だけ聞く |
| 保存フォルダがない | 自動で作る |
| 同じ名前のファイルがある | `_2` を付けて保存し、そう伝える |
| 頼まれていないことをしそうになる（出稿、Web検索、プログラムづくり） | しない。設計書づくりだけにする |

## 14. 使う技術

| 技術 | 役割 | 選んだ理由 |
|---|---|---|
| Claude Code Skill | 手順・質問・設計書の型をClaudeに覚えさせる | ファイル数個で作れる。文章で直せる。費用0円 |
| Markdownファイル | 設計書の保存 | そのままNotionやGoogleドキュメントに貼れる |

- 置き場所：このリポジトリ専用（`.claude/skills/ad-plan/`）
- 別の案：Webアプリ → 費用とサーバーが必要なため、今回は見送り
