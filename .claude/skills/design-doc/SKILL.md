# 設計書作成Skill

このSkillは2つのファイルでできています。作業を始める前に、両方とも最後まで読んでください。

1. **基本ルール**：`references/base-rules.md`
   設計書作成ルールの本体です。進め方、質問方法、標準構成、曖昧な言葉の具体化、禁止事項、チェックリストが書いてあります。設計方法をゼロから作り直さず、必ずこれを土台にします。
2. **個人設定**：`preferences.md`
   このユーザー個人の好みです。基本ルールと食い違う場合は、個人設定を優先します。ただし、次の「絶対に守ること」は個人設定より優先します。

## 絶対に守ること

- 設計書を作っている間は、ユーザーから明確に依頼されるまで実装を始めない。実装計画を作るところまでは、実装に含めない
- 分からない内容を事実として書かない。仮定と未決事項を、決定事項と分けて書く
- 既存のコードやデータがあれば、先に調べてから構成を決める
- 個人情報や認証情報を平文で保存する設計にしない

## 進め方（概要。詳しくは base-rules.md）

1. STEP 1：作りたいツールを聞き、「すでに決まっていること／仮定すれば進められること／実装前に確認が必要なこと」の3つに整理する
2. STEP 2：実装結果に大きく影響する質問だけを、1回最大3問、おすすめ案付きで聞く
3. STEP 3：初稿を作る。不足部分は「仮定」か「未決事項」として明記する
4. STEP 4：base-rules.md の「6. 設計書チェックリスト」で自己チェックし、直せる問題はユーザーに見せる前に直す
5. STEP 5：初稿を見せて、ユーザーの希望に合わせて調整する
6. 最後に「今回決まったこと／Claudeが仮定したこと／実装前に決めること」を示し、修正するか、実装計画へ進むかを聞く
7. ユーザーが望んだら実装計画を作る。実装を始めるのは、はっきり依頼されてから

## 個人設定の更新

ユーザーが新しい好み（「もっと短く」「質問はいらない」など）をはっきり伝え、今後も使いたいと言った場合だけ、`preferences.md` を更新するか確認します。基本ルール（base-rules.md）には個人の好みを書き込みません。
