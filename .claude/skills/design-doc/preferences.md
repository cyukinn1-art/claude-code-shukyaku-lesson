# 個人設定（このユーザーの好み）

> 基本ルール（`references/base-rules.md`）とは分けて管理しています。
> 「確定」はユーザーが言葉で指定したもの、「推定」は今回の進め方から読み取ったものです。推定の項目は、違和感があれば遠慮なく変えてください。
> 最終更新：2026-11-06（初回の設計書作成「女性起業家のためのブランド戦略型 広告設計書ジェネレーター」から作成）

## 設計書の長さ・詳しさ
- 【推定】詳しめで書く。完成条件とテストケースは省略しない
- 【確定】案が複数あるときは、ユーザーが「両方作って」と言えば両方を設計する
- 【推定】案が複数ある場合は、共通部分を「共通編」にまとめ、案ごとの設計書と分ける

## 専門用語
- 【推定】専門用語はできるだけ減らす。使うときは、短い説明を付ける（例：「Skill（Claudeに作業手順を覚えさせる説明書のようなもの）」）

## 質問の出し方
- 【推定】1回最大3問。A／B／Cの選択肢と「おすすめ」を付け、「お任せでも大丈夫」と添える
- 【推定】ユーザーが答えなかった質問は聞き直さず、おすすめ案を「仮定」として置いて先へ進む

## よく作るツール
- 【推定】集客・マーケティング向けのツール（例：女性起業家向けの広告設計）
- 【推定】受講生など、非エンジニアが使うツール

## よく使う技術・技術選定
- 【推定】技術選定はClaudeのおすすめで仮置きしてよい。理由と別案は必ず書く
- 【推定】Webアプリの第一候補：Next.js＋Vercel＋Claude API
- 【推定】自分用ツールの第一候補：Claude Code Skill（追加費用0円）

## 必ず含めたい項目
- 【確定】実装計画まで作る（ただし実装はしない）
- 【推定】実装計画では、費用0円で品質を確かめられる手順を先に置く
- 【推定】実装計画は区切りごとにユーザーの確認を挟む形にする
- 【推定】ユーザーが用意するもの（アカウント、APIキーなど）と、その時期を一覧にする

## 通常は省略したい項目
- （まだ指定なし）

## 出力先・ファイル名
- 【推定】出力先：リポジトリの `docs/design/`
- 【推定】ファイル名：`{2桁の番号}-{英語の短い名前}.md`（例：`00-common-ad-plan.md`、`01-version-a-webapp.md`、`03-implementation-plan.md`）
- 【推定】設計書を作ったら、作業ブランチにコミットして残す
