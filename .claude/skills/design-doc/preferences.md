# 個人設定（このユーザーの好み）

> 基本ルール（`references/base-rules.md`）とは分けて管理しています。基本ルールと食い違うときは、こちらを優先します。
> 「確定」はユーザーが言葉で指定したもの、「推定」は進め方から読み取ったものです。推定の項目は、違和感があれば変えてください。
> 最終更新：2026-11-07（ユーザーの感想「もう少しわかりやすく、質問を減らして。詳しさはちょうどよい」を反映）

## 設計書の詳しさ
- 【確定】今の詳しさでちょうどよい。完成条件とテストケースは省略しない
- 【確定】案が複数あるときは、ユーザーが「両方作って」と言えば両方を設計する。後で1つに決まったら、その案だけの設計書にまとめ直す
- 【推定】案が複数ある場合は、共通部分を「共通編」にまとめ、案ごとの設計書と分ける

## わかりやすさ
- 【確定】もっとわかりやすく書く。具体的には次のとおり
  - 各章の最初に「**ひとことで**：」を1行入れ、その章の要点を書く
  - 一文を短くする（目安は60字まで）
  - 専門用語やカタカナ語は、なるべく普通の言葉に言い換える。使うときは、かっこで短い説明を付ける（例：クリック率（広告を見た人のうち、押した人の割合））
  - 表の列は少なめ（目安は4列まで）にする
  - 「機能要件」「非機能要件」のような硬い見出しは、「主な機能」「困ったときの動き」のような言葉にする

## 質問の出し方
- 【確定】質問を減らす。具体的には次のとおり
  - 初稿の前の質問は**1回だけ、最大2問**まで
  - 選択肢は2つまでにし、「おすすめ」を付ける。「お任せでも大丈夫」と添える
  - 答えがなくても進められることは聞かない。おすすめ案を「仮に置いたこと」として書き、先に初稿を見せる
  - ユーザーが答えなかった質問は、聞き直さない
  - 作るツールの中でも、利用者への質問は少なくする設計を第一候補にする（例：最初に記入シートを1つ出し、追加の質問は最大2問）

## よく作るツール
- 【確定】女性起業家向けの集客・広告のツール（例：ブランド広告設計ナビ）
- 【推定】非エンジニアが使うツール

## よく使う技術・技術選定
- 【推定】技術選定はClaudeのおすすめで仮に置いてよい。理由と別の案は必ず書く
- 【確定】第一候補：Claude Code Skill（追加費用0円）
- 【確定】Skillの置き場所：まずはそのリポジトリ専用（`.claude/skills/`）
- 【推定】Webアプリが必要なときの第一候補：Next.js＋Vercel＋Claude API

## 必ず含めたい項目
- 【確定】実装計画まで作る（ただし実装はしない）
- 【推定】実装計画では、費用0円で品質を確かめられる手順を先に置く
- 【推定】実装計画は、区切りごとにユーザーの確認を挟む
- 【推定】ユーザーが用意するもの（アカウント、APIキーなど）と、その時期を一覧にする

## 通常は省略したい項目
- （まだ指定なし）

## 出力先・ファイル名
- 【推定】出力先：リポジトリの `docs/design/`
- 【推定】ファイル名：`{2桁の番号}-{英語の短い名前}.md`（例：`01-ad-plan-skill.md`、`02-implementation-plan.md`）
- 【推定】設計書を作ったら、作業ブランチにコミットして残す
